# Данные и метаданные: матрица разграничения

Практика разграничения: что течёт по процессу (данные) и что описывает смысл,
происхождение и допустимость этих значений (метаданные). AS-IS, как в остальных
файлах кейса. Числовые параметры бизнес-правил не публикуются.

## 1. Легенда: правило разграничения

Данные — значения, которые меняются от периода к периоду и от человека к человеку:
план, факт, привязки, отсутствия, покрытие.

Метаданные — описания и договорённости, которые задают смысл данных, правила их
получения и границы допустимого: определения, правила расчёта, маппинг, схемы,
владельцы, критерии качества, lineage.

Проверочный вопрос к любому элементу: «это значение этого месяца или это правило,
по которому значение получено?» Первое — данные, второе — метаданные.

Третий класс не путать с метаданными: справочники (коды SFA, коды точек, позиции) —
это reference и master data, то есть данные особого класса: меняются редко и служат
ключами. Сам код и его название — данные справочника; описание смысла кода — метаданные.

## 4. Пограничные случаи: как классифицированы и почему

- Бриф — носитель метаданных (правила), а не данные процесса. Параметры правил
  внутри брифа — значения метаданных; они версионируются вместе с правилом, не с планом.
- DAX-меры отчёта — исполняемые метаданные: маппинг зашит в код смежной зоны.
  Поэтому знание маппинга не передаваемо чтением документации: оно живёт в мерах
  и головах (02).
- Две версии плана — данные со свойством аудируемости. Версионирование значений
  есть; версионирования правил, по которым значения получены, нет. Это разные
  уровни (02).
- Контейнер — данные (история оргструктуры и версии плана) плюс технические
  метаданные схемы, которые до этого документа жили в голове. Слой несёт функцию,
  но не покрыт владением (04).
- Справочник SFA — reference data. Переименование названия при прежнем коде —
  изменение данных справочника, которое ломает связь по названию; контроль этого
  изменения — процедура уровня метаданных, которой нет (02).

## 5. Чего в метаданных нет: сводка разрывов

1. Единый справочник «категория плана → коды SFA + логика» — RDM 10, Metadata 12.
2. Версии бизнес-правил: бриф не версионируется — Governance 3, Metadata 12.
3. Формальный владелец слоя историчности — Governance 3, роли 16.
4. Процедура уведомления об изменении справочника и мониторинг связи — DQ 13, Governance 3.
5. Критерии DQ как документ требований, а не только код фильтра — DQ 13.
6. Lineage до этого документа — Metadata 12; закрыт частично самим кейсом.

## 7. Как использовать матрицу

Три вопроса к любому элементу процесса: что течёт (данные), что описывает
(метаданные), кто владеет описанием (владение). Если на третий вопрос ответа нет —
это разрыв governance, а не разрыв данных. Матрица — рабочий инструмент разбора
AS-IS, не регламент целевой модели.
