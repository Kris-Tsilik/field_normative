# Роли и изменения как есть

## Роли

| Участник | Владеет | Формальная ответственность |
|---|---|---|
| Бизнес-заказчик, каналы MT/TT/TT_MT | правила; консолидация валидации включая BR | владелец правил |
| Владелец канала BR | правила канала BR | владелец правил канала |
| BI-аналитик, команда отчётности | BI-отчёт, загрузка JSON SFA, DAX-маппинг по названию | владелец отчёта |
| Команда SFA | каталог нормативов: коды + названия; переименование без смены кода | владелец источника |
| HR | выгрузка отсутствий из ERP | поставщик входа |
| Аналитик, команда автоматизации | расчёт, контейнеры, свод, DQ-фильтр, инструкции, история | steward-функции без мандата |
| Владелец контейнеров | — | не назначен |

Валидированные данные по BR возвращаются через бизнес-заказчика: он консолидирует
приём, даже когда правила канала принадлежат другому владельцу.

## Изменения

1. Правила: заказчик обновляет бриф → аналитик правит Power Query → пересчёт.
   Версии брифа не формализованы.
2. Схема: аналитик описывает требования → заявка в разработку → реализация
   командой DWH → аналитик перегружает историю с 2024 → обновление отчётности.
   Пример: нормализация широкой таблицы BR, один столбец «тип активности»,
   один «значение».
3. Переименование SFA: команда SFA меняет название без уведомления downstream
   → тихий сбой маппинга → обнаружение через жалобу. Путь изменения существует,
   но не контролируется.
