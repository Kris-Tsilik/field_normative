# Нормативы полевых активностей: описание процесса в терминах DAMA-DMBOK2

Кейс из практики. FMCG-компания, полевые продажи.

## Что это

Описание реального производственного процесса AS-IS: ежемесячный расчёт плановых
нормативов супервайзеров, корректировка плана прошлого месяца и подготовка данных
для BI-отчёта выполнения. Процесс разобран через области знаний DAMA-DMBOK2:
что реализовано, что частично, где разрывы.

Это не регламент и не проект миграции. Описано только то, что существует.
Целевая архитектура и перенос расчётов в хранилище в кейс не входят.

## Роль автора

Аналитик команды автоматизации. Выполняла функции Data Steward без формального
закрепления роли: расчёт и загрузка данных, DQ-фильтры, нормализация таблиц,
инструкции для команды отчётности, эскалация проблем качества на источник.

Инструмент расчёта на Power Query с ODBC SQL-подключениями к DWH — мой. 
Меры, DAX и модель отчёта — зона BI-аналитика; в кейсе они описаны как смежная зона, не как
моя работа.

## Подтверждённые результаты

- Цикл подготовки нормативов сокращён с 3 дней до 4 часов.
- Процесс перешёл к одному аналитику от трёх специалистов разных служб.
- 3 интеграционных контейнера PostgreSQL в контуре.
- Исторические данные мигрированы под текущий формат с 2024 года.

## Анонимизация

Названия клиента, отраслевая специфика, систем, отчётов, схем, продуктов и команд
заменены обобщёнными. Числовые параметры бизнес-правил не публикуются.
Оргструктура, имена, должности и численность не приводятся. Внутренние имена
файлов, персональные данные и скриншоты систем отсутствуют.

## Ключевые находки

1. Связь плана и факта в отчёте идёт по названию, не по коду. Источник может
   переименовать норматив, не меняя код и никого не уведомив. Ошибка тихая:
   числа правдоподобны, но неверны. Детектор — жалоба полевого сотрудника
   бизнес-заказчику. Разбор: 02-data-quality.md.
2. Контейнер — слой историчности, которого нет в DWH: оргструктура по месяцам
   и две версии плана. При этом формальный владелец слоя не назначен, и слой
   находится вне контура владения корпоративной функции управления данными.
   Разбор: 04-metadata-lineage.md.
